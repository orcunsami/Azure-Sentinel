| 3.0.2       | 01-10-2026                     | Import now processes each alarm page as it is read and verifies that every page was imported before the run completes. The Synced tag is applied after the SOCRadar write is confirmed. Aligned the critical alarm rule's severity filter and alarm URL with the SOCRadar platform format. Incident severity write-back to SOCRadar is governed by SyncSeverity (on by default) and only ever raises a severity, never lowers it. Added optional IoC extraction and bookmark-relation enrichment for new incidents, with a retry on transient relation failures. All Azure Resource Manager and Log Analytics endpoints are resolved from template variables. Import keeps its run window in a storage account table deployed with the playbook, so a run resumes from where the previous one finished. Alarms imported in a closed state are tagged as already synced. Sync looks back 24 hours for closed incidents without the Synced tag instead of twice the polling interval, and a run whose closed-incident query failed on a page ends Failed. The Alarm Volume Spike rule compares each alarm type with its own 7-day average. The analytic rules no longer require a data connector the solution does not ship. The Alarm Overview hunting query counts distinct alarms. New IncidentMode parameter on the Import playbook, AlertBacked by default: the import writes each alarm to SOCRadar_Alarms_CL and five scheduled analytics rules (lookalike and phishing domain, credential exposure, data leak and PII, vulnerability and CVE, other alarms) raise one alert and one incident per alarm, with the entities and custom details of that alarm type and a plain-text description, so the incidents are also listed in the Microsoft Defender portal; an automation rule labels them SOCRadar. Direct keeps the previous behaviour. EnableCredentialRule switches the credential rule off, DeploySampleAutomationRules adds two example automation rules. Redeploying an existing Direct install without setting IncidentMode switches it to AlertBacked: alarms inside the first import window get a second, rule-created incident, so close the old ones. The incident appears about 20 to 26 minutes after the alarm is imported. Sync resolves the alarm from the incident title, or from the incident's URL entity when Microsoft Defender renamed it. The Unsynced Closed Incident rule falls back to the alarm id on the backing alert. The dashboard workbook adds alarm type, latest state, alarm-to-incident and sync status panels. New SOCRadar-IOC-Enrichment playbook: when an incident is created it looks up the incident's entities (IP, domain, URL, file hash) in SOCRadar IOC Enrichment and posts the risk score, categorization and threat actors as an incident comment. |
